# Locked decisions

Decisions below are approved. Implement them. A change needs a new dated entry, or a dated amendment on the row, and a user request.

`draft1/` assumed authenticated board CRUD, cookies, PostgreSQL from the first release, and a separate Node collaboration service. Those assumptions are withdrawn for the MVP.

| ID | Decision |
|---|---|
| D2-001 | Working title remains `segl`. |
| D2-002 | MVP is nine fixed collaborative Excalidraw slots. Network objects, inventory import, login, and protected workspaces come later (`ROADMAP.md`). |
| D2-003 | One Python process serves the built web app, the HTTP API, and the collaboration WebSocket. Nginx is the TLS reverse proxy. There is no Node process in production. |
| D2-004 | The browser app is React + TypeScript, built with Vite, embedding `@excalidraw/excalidraw`. The web tooling is D2-023. |
| D2-005 | Slots are numbered 1–9, created at first startup, and never created or deleted by users. Each slot has one shared scene and one shared title. The default title is `Workspace N`. |
| D2-006 | First visit opens slot 1. A later visit to segl's root opens the last slot stored in `localStorage`. A link to `s/N` always opens slot N. |
| D2-007 | One frontend build serves every mount point, and segl has no setting for the path it is mounted under. segl serves at its own root. A reverse proxy gives it a host name of its own (`https://board.example.com/s/1`) or a path on an existing site that the proxy strips (`https://dev.example.com/board/s/1`, the example path in `deploy/nginx/`). The page asks for its assets, the API, and the WebSocket relative to itself. Amended 2026-11-11 (T00): replaces `base_path` in TOML, following Sunstone. |
| D2-008 | The web interface uses no cookies in any phase. Later login will use an `Authorization` bearer token stored in `localStorage`. |
| D2-009 | Anyone who can open the URL can view a slot and see live updates. A site-wide `edit_token` in TOML gates mutations. An empty token means every viewer may also edit. |
| D2-010 | Persistence is SQLite behind a repository interface. PostgreSQL is a later swap, not an MVP dependency. App configuration is TOML. CSV, JSON, and TOML inventory import is later. |
| D2-011 | The head scene is flushed within 200 ms of a change, on last disconnect, and on shutdown. A user-visible revision is recorded at most about once a second, on last disconnect, and on restore or import. The latest 50 revisions per slot are kept. |
| D2-012 | Display labels are assigned from `display-names.txt` round-robin, plus a server-wide counter that never repeats (`Alpha1`, `Bravo2`). The browser keeps the label in `localStorage`. A manual rename replaces the whole label and is title-cased. Automatic names use the file's spelling verbatim. |
| D2-013 | The menu shows the number of live WebSocket connections on the current slot. Activating it lists those participants. |
| D2-014 | Future protected boards use `/{team}/{project}/{board-slug}`. The MVP does not implement that tree. The first path segment `s` stays reserved for slots. |
| D2-015 | Development and automated tests run in a container under rootful Docker, rootless Docker, or rootless Podman. The MVP production install is a `.deb` that places a uv-pinned CPython and a virtualenv under `/opt/segl`, supervised by systemd, behind host nginx. A production container image is a second install method after the MVP gate. Amended 2026-11-11 (T00): rootful Docker allowed for development. |
| D2-016 | Python tooling is uv, ruff, and ty. The Python pin is the exact `runtime.python` value in `versions.toml` (3.15.2). `.python-version` mirrors it. The pin follows the newest stable CPython that uv can install, patch or minor, under the release policy in D2-020. Amended 2026-11-11 (T00): exact patch pin, kept current through uv. |
| D2-017 | Collaboration is a segl WebSocket protocol. The server reconciles Excalidraw elements by id and version and checkpoints the scene. It does not speak the upstream `excalidraw-room` socket.io protocol unless a spike shows the embed requires it, and even then the process remains the one Python service. |
| D2-018 | JSON export and import are in the MVP. Import is an edit: it bumps the scene epoch, requires the edit token when one is set, and writes a revision. PNG and SVG export are whatever the embedded editor already shows. No custom image-export task. |
| D2-019 | The project license is Apache License 2.0. The text is `LICENSE` at the repository root. New source files carry the header in `CONTRIBUTING.md`, with `Copyright 2026 segl contributors`. Excalidraw and other dependencies stay under their own licenses. Attribution those licenses require goes in `NOTICE` when the dependency is added. |
| D2-020 | `versions.toml` is the only version list: application, Python, Node, and direct dependencies. The program reads it to display or check a version. Every component moves to its newest stable release, however recently it was published. One is held back only after it fails the tests, as a `[held.*]` entry with the reason, and is tried again when a newer release appears. `scripts/release.py` checks currency again when a release is published, and publishes only from a clean `main` whose CI passed. Release notes use the shape in `RELEASING.md`, including a first-party `cloc` count ahead of the version table and a collapsed list of lockfile sub-dependencies. `CHANGELOG.md` is the summary history. `journal/YYYY-MM-DD-short-title.md` is the narrative. GitHub Releases, including the `.deb` asset, are on from the first publishable release. PyPI stays off until `publish.pypi` is set true, which waits for a build worth demonstrating. Amended 2026-11-11 (T00): the vakr and Sunstone release policy. |
| D2-021 | The GitHub repository contains the whole project except gitignored secrets and build output. `draft1/` is frozen history. `draft2/` is the agent workbook: status, tasks, and agent rules. `docs/` is the contributor and operator manual. Neither draft folder is gitignored. |
| D2-022 | The repository is public at `https://github.com/robert-patrick-texas/segl`, default branch `main`. Commits carry a `Signed-off-by` line (`git commit -s`). Vulnerability reports go through GitHub private vulnerability reporting. Added 2026-11-11 (T00). |
| D2-023 | The web package uses npm: exact versions in `web/package.json`, `web/package-lock.json`, and `web/.npmrc` with `engine-strict=true`. Node is the LTS release named in `web/.node-version` and mirrored in `versions.toml` `runtime.node`. Vitest runs unit tests. `@playwright/test` runs browser tests against Python serving the production build. `tsc --noEmit` type-checks, and Prettier formats. This matches Sunstone. Added 2026-11-11 (T00). |
| D2-024 | The documentation is published to GitHub Pages at `https://robert-patrick-texas.github.io/segl/` from GitHub Actions (`.github/workflows/pages.yml`) on every push to `main`. `scripts/build_docs.py` builds it with `tools/md2html`, copied from vakr and kept portable. Every Markdown file becomes a page, `README.md` is the index, and every page's left-hand index opens with the project name linking to the repository. Pictures live in `images/` at the repository root. A broken link, anchor, or image fails the build. Added 2026-11-11 (T00b). |
| D2-025 | The editor is `@excalidraw/excalidraw` 0.18.1, the newest stable release on 2026-11-12, embedded from npm unmodified. `versions.toml` holds the pin. The package exports a reconcile helper, `reconcileElements(localElements, remoteElements, localAppState)`, and segl follows it: from T06 the client calls it, and the server applies the same rule to two copies of an element. The copy with the higher `version` wins. On equal versions the copy with the lower `versionNonce` wins. The helper also keeps this browser's own copy of an element it is editing, resizing, or creating, which only the client can know. A scene document's `source` is `segl` (`window.EXCALIDRAW_EXPORT_SOURCE`), not the page's origin, so a stored or exported scene does not carry the site's host name. Added 2026-11-12 (T04). Amended 2026-11-12 (T06): the client calls the helper in `web/src/canvas/editor.ts`, and the server's rule is `src/segl/reconcile.py`. `tests/reconcile_cases.json` is one table of cases that holds the server's rule (pytest), the editor's helper (`web/e2e/reconcile.spec.ts`), and the client's rule for what to send (Vitest) to the same answers. A deletion has no priority of its own: it is an edit with a version like any other. |
| D2-026 | The page loads nothing from another host (S-014). Vite bundles the editor's code, styles, locale chunks, and interface font into `web/dist/assets/` under content-hashed names. The canvas fonts are different: the editor fetches them at run time, from `window.EXCALIDRAW_ASSET_PATH` and then from a public CDN (`esm.sh`). The build copies them from the package's `dist/prod/fonts` to `web/dist/fonts/` (`web/scripts/editor-fonts.ts`), and the page sets `EXCALIDRAW_ASSET_PATH` to segl's root URL before the editor module loads (`web/src/canvas/environment.ts`). `web/e2e/mount.spec.ts` refuses every request to another origin, places a text element so that a canvas font is fetched, and fails if any request left the mount. What a person starts in the editor that names another site by design is unchanged: the library browser, embedded pages, and the links in the editor's menu. Added 2026-11-12 (T04). |
| D2-027 | uvicorn serves the collaboration WebSocket with the `websockets` package (`ws="websockets-sansio"`), a direct dependency pinned in `versions.toml`. Plain uvicorn has no WebSocket protocol of its own, and `websockets` also gives the tests a client. The protocol carries no color for a participant: the pinned editor draws a remote cursor in a color it derives from the collaborator's id and ignores one it is given, so every browser already shows a connection in the same color, and a color segl chose would match no cursor. The edit token is read once per connection, from `hello`. Added 2026-11-12 (T06). |
| D2-028 | An image's bytes are a file outside the scene, as in the pinned editor. The editor keeps each image's bytes as a `data:` URL in a table of files beside the elements, under a file id it makes itself (the SHA-1 of the file the person chose, as 40 hex digits). An image element names that id in `fileId`, and the scene document the editor serializes for storage has no files. segl follows that. The bytes are stored once, as a file under `assets_dir` named by their SHA-256, through `POST api/v1/slots/{n}/assets`, and read back through `GET api/v1/assets/{hash}`. Migration `0002_slot_files.sql` adds `slot_file`, which says which hash a slot's file id means, and a `files` message tells the room. A row of `slot_file` is never changed or deleted, so a file id keeps the bytes it was first given and a revision that names it keeps its image. The bytes are the editor's own encoding of the image, which it resizes above 1440 pixels, and not the file the person chose. An upload names one of the editor's nine image types, and segl does not look inside the bytes. They are served as `application/octet-stream` with `nosniff` and a sandboxing `Content-Security-Policy`, and never as an image or a page of the site: the browser builds the `data:` URL itself from the type in the file list. Added 2026-11-12 (T07). |
| D2-029 | What "saved" means. A browser numbers the `elements` and `files` messages it sends (`seq`), and the server answers `saved` with the number of the newest one that is in the slot's head on its disk. The bar says `Saving…` from the edit until that answer, the upload of an image's file included, and then `Saved`. The stored head is the room's whole scene with its deleted elements, so a restart does not forget a deletion, inside the document the head already held, whose other parts segl leaves as they are. The elements of one slot come to at most `max_scene_bytes` as JSON, and a batch that would take them over is refused with `scene_too_large`. Deleted elements are never dropped from a scene. Upstream's own collaboration drops them after a day, and segl may need the same once a slot has been edited for long. Added 2026-11-12 (T07). |
| D2-030 | A restore can be undone, and says who made it. Before the server puts a revision's scene in place of a slot's scene, it writes what the slot's room holds to the head and keeps it as a revision, whatever the age of the newest one. The restore then writes its own revision at the next epoch, so the two newest revisions are the scene that was replaced and the scene put in its place. Both writes are the slot saver's, under the one lock its head flushes take (`src/segl/saver.py`), and the revision to restore is read before either, because the first may drop the oldest revision. `POST api/v1/slots/{n}/restore` takes `displayName` beside `revision`, the label the browser stores, for the revision's `authorLabel`: a request has no other name, and the label is as unverified as every label in this phase. The revision table has no column for what kind of write made a row. A row written by a restore is the first of its epoch, and the History control marks it from that. Reading the history needs no token. The control reads the list when it is opened and when the epoch moves, not live, and a restore there takes two presses. JSON import (T09) replaces a scene through the same saver method. Added 2026-11-12 (T08). Amended 2026-11-12 (T09): an import starts an epoch too (D2-031), so the mark on the first row of an epoch reads `replacement` and covers both, and the table still has no column that says which. The import has a saver method of its own, `put`, which shares the restore's steps and its lock. |
| D2-031 | JSON export is the editor's, and JSON import is segl's. Export is the editor's own menu entry, which writes a `.excalidraw` document with the files of its images inside it. segl only names the file, after the slot's title. The editor's ways to open a scene file are closed, because each puts the file in one browser's canvas and not in the slot: its menu's Open and Ctrl+O are off, and a file dropped on the canvas that is neither an image nor a library goes to segl's import. The bar's Import control posts the file as it is to `POST api/v1/slots/{n}/import`, after a second press. The server takes the document's elements and the files they name, and nothing else: `appState` is left, as a slot does not share its background or its grid. The files' bytes are stored as uploads are (D2-028), and their ids join the slot's file list in the write that starts the new epoch. The stored scene is the slot's own document with the imported elements, in drawing order. The steps are a restore's (D2-030): the slot's saver keeps the scene being replaced as a revision, writes the imported one at the next epoch with a revision of its own, and every connection is sent `scene`. So an import can be undone from the history. Who imported comes in the `X-Segl-Display-Name` header, percent-encoded, because the body is the document. The document is read strictly: its `type` is `excalidraw`, every element has an id of its own, a named file is an image in a `data:` URL, and a number JSON cannot write, such as `1e999`, refuses it. The body is at most `max_scene_bytes`, and so are the elements as they are stored. Added 2026-11-12 (T09). |
| D2-032 | A link's edit token is proven before it is stored. A shared link carries the token in its fragment, `#e=<token>`, percent-encoded, on any slot or on segl's root. The page takes the fragment out of the address at once, says `hello` with the token, and writes it to `localStorage` under the `basePath` key only once `welcome` says that the connection may edit. A token the server refuses is never stored, and when the browser already has a stored token the page goes back to that one. The reason is that any page on the web can make a browser open a link, so a link that stored whatever it carried would let a stranger take a working token away from every editor who followed it. The token is what a request header carries whole: 1 to 256 printable ASCII characters with no space at either end. segl does not start with another, and the page takes no other from a link or from storage, since a browser cannot send it in `X-Segl-Edit-Token`. Added 2026-11-12 (T10). |

## Open

None. T07 settled the image file model as D2-028, T08 what a restore keeps as D2-030, T09 what an import takes as D2-031, and T10 when a link's edit token is stored as D2-032.

## Decision protocol

When a task discovers that a locked decision cannot be implemented as written, set `Blocked: yes` in `draft2/STATUS.md` and append the evidence. Do not silently substitute PostgreSQL, cookies, a Node room server, free-form board CRUD, mandatory login, or a base-path setting.
