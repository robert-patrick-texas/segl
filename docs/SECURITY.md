# Security (MVP)

The network perimeter is the access boundary for reading a slot. nginx listens on the addresses the site chooses. The Python process listens on `127.0.0.1` only. Slots are shared whiteboards: anyone who can open the URL can watch live, and can edit when no edit token is configured. They are not a place for protected network inventory. That data has no tables and no routes in this phase.

## Required controls

- TLS at nginx for any shared deployment. The application generates relative URLs so it does not terminate TLS itself.
- `edit_token` compared with a constant-time compare. Wrong and missing tokens both yield a view-only connection.
- Token storage on the client is `localStorage` under the `basePath` key. A shared link uses the `#e=` fragment, which the page strips after copying it into `localStorage`.
- No `Set-Cookie` on any response. No session middleware. No credentialed CORS.
- Reject a mutating request whose `Origin` header is present and does not match its `Host` header, host and port, with `403` and `bad_origin`. nginx passes the browser's `Host` with its port (`deploy/nginx/segl-proxy.conf`). WebSocket upgrades follow the same check, and are refused in the handshake. The check is middleware in front of every route (`src/segl/origin.py`): any method but `GET`, `HEAD`, and `OPTIONS` is a mutation, on any path. A port left out is the scheme's own, 80 or 443. An origin that is not `http` or `https`, such as the `null` of a sandboxed page, matches nothing. A request without `Origin`, such as one from `curl`, is not a browser's cross-site request and passes. Reads are not checked, and segl sends no CORS header, so a page on another site cannot read an answer.
- The collaboration socket: a connection is in no room until its `hello`, and has 10 seconds to send it. A message is at most `max_scene_bytes`. The server reads `id`, `version`, `versionNonce`, and `index` of an element and relays the rest as data, and each browser's editor checks an element before it holds it. A message it could not write back as JSON is refused whole: `NaN`, `Infinity`, and a number too large to hold, such as `1e999`, which would otherwise be stored and leave the slot's scene unreadable to every browser. A browser that stops reading is disconnected once 1024 messages or 16 MiB wait for it. The number of connections is not limited: the network perimeter is the limit.
- Body limits: `max_asset_bytes` default 10485760, `max_scene_bytes` default 52428800. nginx allows 52 MiB, so segl's own limits answer first.
- Display-name allocation: at most 30 allocations per client address in any 60 seconds, counted in memory, so a restart forgets the count. A call counts when it is admitted, whether or not the allocation then succeeds. The call after the 30th gets `429` with `rate_limited`, takes no name, and is not counted, so a client that keeps asking is admitted again once its oldest counted call is a minute old. An address whose counted calls are all a minute old is dropped from the table at its next sweep, which runs once a minute while names are being asked for. The client address is the `X-Forwarded-For` value when the connection comes from an address in `trusted_proxies` (default `127.0.0.1` and `::1`), and the connection's own address otherwise. uvicorn applies that rule (`proxy_headers`, with `trusted_proxies` as its allowed addresses), so the access log shows the same address. nginx overwrites that header with the address it sees, so a client cannot choose it.
- Uploaded files (D2-028). An upload is a mutation: it needs the edit token when one is set, and passes the Origin check. Its `Content-Type` must be one of the editor's nine image types, and its body at most `max_asset_bytes`. segl does not look inside the bytes, so a file is whatever a browser sent. It is therefore served as `application/octet-stream` with `X-Content-Type-Options: nosniff` and `Content-Security-Policy: default-src 'none'; sandbox`, and never under an image or page type: an uploaded SVG with a script in it, opened by its URL, is a download that runs nothing and cannot read the edit token in `localStorage`. The page fetches the bytes, builds a `data:` URL, and the editor shows it in an image element, where a script does not run.
- Uploaded-file reads (`/api/v1/assets/{hash}`) use a SHA-256 hex name under `assets_dir`. A name that is not 64 lowercase hex digits is a `404` before any path is built, so no text a browser sends is joined to the folder. Reading needs no token, as viewing a slot needs none. No route lists, replaces, or deletes a file.
- A `files` message, which says that a file id means some uploaded bytes, is refused unless segl has those bytes, and a file id keeps the bytes it was first given. So nobody can point an image that is already on a slot at other bytes.
- The number of uploads is not limited, and nothing removes a file once no scene names it. A slot's elements are limited to `max_scene_bytes` together (`scene_too_large`). The network perimeter and the edit token are the limit on who can fill the disk.
- The history. Anyone who can open the URL can read a slot's revisions, as anyone can view the slot: the latest `history_limit` scenes (50), which include what has since been deleted from the canvas. Deleting something does not take it out of the history, and nothing but newer revisions pushes a revision out. A restore is a mutation: it needs the edit token when one is set, and passes the Origin check. The name on a revision is the display name a browser sent, which nobody has verified, as with every label in this phase.
- JSON import (D2-031). An import is a mutation: it needs the edit token when one is set, checked before the body is read, and passes the Origin check. Its body is at most `max_scene_bytes`. The document is data from a browser, and is read strictly. segl keeps its elements, of which it reads `id`, `version`, `versionNonce`, `index`, and `fileId`, and the files those elements name. It reads nothing else in it. A file's bytes are taken out of the document and stored and served as an upload's are, under the same types and the same size limit, so an SVG inside an imported file is no more a page of this site than an uploaded one. A file id the slot already has keeps its bytes. A number JSON cannot write, such as `1e999`, refuses the document: the server would otherwise hand every browser a scene it could not parse. A refusal's message says where the document is wrong and repeats nothing from it. The name on the import's revision comes from the `X-Segl-Display-Name` header, and is as unverified as every label. The editor's own way to open a file is off (`ARCHITECTURE.md`, export and import), so that a file cannot reach the shared scene past the gate's one question.
- SQL parameters only. Slot numbers are integers 1–9. A revision number in a path is 1 to 16 digits, and in a restore's body a whole number in the same range, before it reaches a query.
- Logs may include slot, epoch, revision, status, and byte size. Logs omit the edit token, cookies, authorization headers, and scene bodies. A WebSocket's log line is its path, `/collab?slot=N`. Display names and elements are not logged. A head flush that fails is logged with the slot's number and the database's error. An upload's log line is its path, and a read's has the hash. An import's log line is its path: not the file's name, its elements, or who imported.
- Secrets live in `/opt/segl/etc/segl.toml`. When a token is set, that file is mode `0640` and group `segl`. The service user cannot write the Python install or the virtualenv.
- The packaged word list is read as text. It is not executed and it is not imported as code.
- Runtime does not call a SaaS API. Fonts and the editor bundle are served by this process.
- CSV and JSON formula injection matters later, at L-002. There is no inventory import in P0. Scene JSON, drawn or imported, is stored and returned as data, not rendered as HTML.

## Deferred with the later phases

Login, bearer tokens, protected workspaces, inventory credentials, encryption at rest, and SSO are L-004 and L-006. Do not add stub user tables or a login route in P0.

A pilot that passes these controls is still an open shared whiteboard. Operators who need to keep a diagram private either rely on network controls or set `edit_token` and treat the URL as untrusted for writes. Viewers of a token-protected slot can still see the drawing.
