# Changelog

Summarized history of changes to source and documents. Newest release first. The release script turns `Unreleased` into the next release note. Keep the one-to-three sentence summary, then only the topic headings that have bullets: New, Changed, Fixed, Additional Notes.

## Unreleased

The project is specified, licensed, and public on GitHub. A Python service reads its settings, keeps nine slots in SQLite, and serves them, and a browser application shows each slot as an Excalidraw canvas under the segl bar, where each browser has a display name. People on the same slot draw together live, and what they draw, images included, is saved and survives a restart. A slot's earlier versions are listed in the bar and can be restored, and a slot can be exported to an Excalidraw file and imported from one. With an edit token set, a browser without it watches and cannot change anything, and a link that carries the token lets a browser edit. CI and a dev container check both, including through nginx at `/board/`.

### New

- Apache License 2.0 and the nine-slot MVP specification.
- One version manifest (`versions.toml`), a release script, this changelog, and `journal/` for the project narrative.
- The public repository <https://github.com/robert-patrick-texas/segl>, with GitHub private vulnerability reporting.
- nginx files in `deploy/nginx/`. They hold an upstream and WebSocket map, proxy settings (forwarded client address, a body limit above segl's own, timeouts, gzip), a `/board/` mount, and two example sites.
- `docs/DEVELOPMENT.md` lists the development host's tools, the checks, and the dev loop.
- The documentation site at <https://robert-patrick-texas.github.io/segl/>: every Markdown file as a page, with an index of all pages that opens with a link to the repository. `scripts/build_docs.py` builds it with `tools/md2html`, copied from vakr. Pictures go in `images/`. A broken link, anchor, or image stops the publish (D2-024).
- The Python project: package `segl` under `src/segl`, built with hatchling, with FastAPI and uvicorn. `uv run segl` serves `GET /api/v1/health` on `bind` (default `127.0.0.1:8888`), and `segl --version` prints the application version from `versions.toml`, a copy of which the wheel carries.
- The checks: `uv run pytest`, `uv run ruff check .`, `uv run ruff format --check .`, and `uv run ty check`. Tests hold `pyproject.toml`, `.python-version`, and md2html's inline metadata to `versions.toml`, and check every source file for the license header.
- The release command (`scripts/release.py`, `docs/RELEASING.md`): `check --gate` covers Python, every direct dependency, and the pinned GitHub Actions. `upgrade` moves one component at a time and holds one that fails the suite. `cut` writes the version and the changelog section. `publish` runs its preflight, tags, and creates the GitHub Release.
- CI (`.github/workflows/ci.yml`) runs those checks on pushes to `main` and on pull requests.
- The dev container, `deploy/Containerfile`: Ubuntu 26.04 and uv, running the suite with uv's Python.
- Every setting in `docs/DEPLOY.md`, with `deploy/segl.toml.example` as the file the package will install. Without `--config`, segl uses the development defaults and reads a local `segl.toml` when one exists. A key segl does not know, or a value it cannot use, stops it at startup with a message that names the key.
- `GET /api/v1/config` returns `{ "editRequired" }`.
- segl believes `X-Forwarded-For` and `X-Forwarded-Proto` only from `trusted_proxies`, which takes addresses and networks. It sends no redirect of its own, so a trailing slash on an API path is a `404`.
- Mount tests: `uv run pytest` runs nginx with the `deploy/nginx/` files in front of a real segl process, at `/board/` and at a host root (`tests/test_mount.py`, `tests/harness.py`). They skip without nginx or openssl. The dev container and CI install nginx and set `SEGL_REQUIRE_NGINX=1`, which turns the skip into a failure.
- SQLite storage (`src/segl/repository.py`, `docs/DATA-MODEL.md`). segl creates the `database` file at startup, in WAL mode, applies the numbered SQL files in `src/segl/migrations/`, and adds slots 1–9 as `Workspace 1` to `Workspace 9`. A database it cannot open, or one from a newer segl, stops it with exit status 1.
- `GET /api/v1/slots`, `GET /api/v1/slots/{n}`, and `GET /api/v1/slots/{n}/scene`. Anything but `1` to `9` for `{n}` is a `404` with `invalid_slot`.
- A new slot's scene is the editor's own empty scene, `src/segl/empty_scene.json`, captured from the running editor. A browser test compares the file with what the pinned editor produces. A head that still holds the earlier placeholder `{"elements":[]}` gets the empty scene at startup.
- Every error has the `{ "error", "message" }` shape, including an unknown path (`not_found`), a method a path does not take (`method_not_allowed`), and a failure inside segl (`internal_error`).
- The web application, `web/`: Vite, React, TypeScript, and React Router, embedding `@excalidraw/excalidraw` 0.18.1 unmodified (D2-025). The segl bar sits above the canvas with slot buttons 1–9, the slot's title, room for the presence count, the notice that the workspace is shared, and the application version from `versions.toml`. Only `web/src/canvas/` imports Excalidraw.
- Navigation: segl's root opens the last slot this browser used, kept in `localStorage` under a key that carries the mount path, or slot 1. `s/N` opens slot N, and any other `s/...` goes to slot 1.
- Python serves the build. `web_dir` is a new setting: `/opt/segl/app/web/dist` in production, `web/dist` in a checkout. `/` and `/s/{n}` return the page with file URLs relative to that page and `window.SEGL_CONFIG = { root, editRequired }`, so one build works at a host root and under `/board/`. Without a build, segl serves the API alone and says so when it starts.
- The page asks for nothing outside segl (S-014, D2-026). The build copies the editor's canvas fonts into `web/dist/fonts/`, and the page points the editor at them in place of its public CDN.
- Web checks: `npm --prefix web run check` (`tsc --noEmit`), `test` (Vitest), `format:check` (Prettier), `build`, and `e2e` (Playwright). The browser tests run against Python serving the build, directly and behind nginx with the `deploy/nginx/` files, at a host root and at `/board/`. They refuse every request to another origin and fail if the page attempted one. `PW_WS_ENDPOINT` uses a browser running elsewhere.
- CI runs the web checks, the build, and the browser tests. The dev container has Node and runs the web checks and the build. `scripts/release.py upgrade` and `cut` run them too.
- `versions.toml` lists Node 26.13.1 and every direct web dependency. `web/package.json`, `web/package-lock.json`, and `web/.node-version` mirror it, and a test holds them to it. `scripts/release.py check` covers them.
- Display names (S-009). `deploy/display-names.txt` is the packaged word list, 190 words. `POST /api/v1/display-name` returns the next name, such as `Alpha1`, then `Bravo2`, from the word file and a counter in SQLite that never repeats. One client address gets 30 names a minute. The next call is a `429` with `rate_limited` and `Retry-After`.
- segl reads the `display_names` file when it starts. A file that is missing, has a line that is not a word of 1–10 letters, or has no words stops it with exit status 1.
- The segl bar shows this browser's name after `You:`. A new browser asks the server once and keeps the answer in `localStorage`, across reloads, slots, and tabs. The name is a button: a typed name is title-cased (`john smith` becomes `John Smith`), kept the same way, and shown only in that browser until live collaboration exists.
- `tests/display_name_cases.json` holds the browser's title case and the server's to one table of cases.
- Live collaboration (S-002). `/collab?slot=N` is a WebSocket, and each slot has a room in the server. An edit in one browser reaches the others on the slot, with each person's cursor and name. Two edits to one element are settled as the pinned editor settles them: the higher `version` wins, then the lower `versionNonce`. A deleted element stays deleted. `tests/reconcile_cases.json` holds the server, the editor's `reconcileElements`, and the browser's own rule to one table.
- The segl bar shows who is on the slot: the number of connections, which opens a list of their names (S-010), and the state of the connection, `Connecting…`, `Live`, or `Disconnected` (S-013). With the socket down the canvas stays usable. The page reconnects by itself and sends what was drawn meanwhile, without overwriting a newer edit.
- The slot's title is a button in the bar. `PATCH /api/v1/slots/{n}` stores a new one, 1–80 characters, and every browser on the slot shows it at once.
- A rename reaches everyone on the slot, title-cased by the server as well.
- The edit gate on the server (S-008). With `edit_token` set, a connection whose `hello` lacks the token watches live and cannot change elements, and a `PATCH` without the `X-Segl-Edit-Token` header is a `403` with `view_only`. The page puts the editor in view mode for such a connection.
- The Origin check. A mutation, or a WebSocket handshake, whose `Origin` does not match `Host` is refused with `403` and `bad_origin`.
- `websockets` 17.4 is a dependency: uvicorn serves the socket with it, and the tests connect with its client (D2-027).
- Saving (S-004). segl writes a slot's scene to its head 0.2 seconds after an edit (`head_flush_seconds`), when the last browser leaves the slot, and when it is stopped with SIGTERM. `src/segl/saver.py` is the flush, and `docs/DATA-MODEL.md` has its rules. A stored scene keeps its deleted elements, so a restart does not forget a deletion (D2-029).
- `saved`. A browser numbers the messages it sends (`seq`), and the server answers `saved` with the number of the newest one that is on its disk. The bar says `Saving…` from an edit until that answer, and then `Saved` (S-013).
- History rows (the storage of S-005). A flush adds a revision at most once a second while people draw (`history_interval_seconds`), and always when the last browser leaves and when segl stops. The newest 50 per slot are kept (`history_limit`). No route lists them yet.
- Images (S-012, D2-028). The bytes of an image are a file under `assets_dir`, named by their SHA-256. `POST /api/v1/slots/{n}/assets` stores them, `GET /api/v1/assets/{hash}` returns them, and a `files` message on the socket says which file id they are. The other browsers on the slot fetch the file and draw the image, and a browser that loads the slot later gets the file list with the scene. Migration `0002_slot_files.sql` adds the list to the database.
- An uploaded file is served as `application/octet-stream` with `nosniff` and a sandboxing `Content-Security-Policy`, whatever was uploaded. An upload needs the edit token when one is set, and names one of the editor's image types (`unsupported_media_type` otherwise).
- The elements of one slot are limited to `max_scene_bytes` together. An edit that would go over is refused with `scene_too_large`.
- segl makes `assets_dir` when it starts, and stops with exit status 1 when it cannot write there. A backup is the database file and that folder together.
- Browser tests for all of it: `saving.spec.ts`, `images.spec.ts`, and `durability.spec.ts`, which kills a segl of its own with SIGKILL and starts it again (T-005, T-006, T-007).
- History (S-005, D2-030). `GET /api/v1/slots/{n}/revisions` lists a slot's revisions, newest first, and `GET /api/v1/slots/{n}/revisions/{revision}` returns one with its scene and its files. Neither needs the edit token.
- Restore. `POST /api/v1/slots/{n}/restore` with `{ "revision", "displayName" }` puts a revision's scene in place of the slot's, at the next epoch, and every browser on the slot is sent it. The scene that was replaced is kept as a revision first, so a restore can be undone by restoring that one. It needs the edit token when one is set. New error codes: `revision_not_found` (404) and `invalid_revision` (422).
- The History control in the bar lists the revisions with the time and the display name of each, marks the ones a restore wrote, and restores one in two presses. A browser without the edit token sees the list without the restore buttons. The list stays inside the page on a narrow screen.
- Tests for it: `tests/test_history.py`, more of `tests/test_saver.py` and `tests/test_room.py`, and `web/e2e/history.spec.ts` (T-011, and the history part of T-008).
- JSON import (S-011, D2-031). `POST /api/v1/slots/{n}/import` takes the file the editor's export writes, of at most `max_scene_bytes`, and puts its elements in place of the slot's scene at the next epoch, for every browser on the slot. The files of its images come out of the document and are stored as uploads are. The scene that was replaced is kept as a revision first, as with a restore, so an import can be undone. Who imported comes in the `X-Segl-Display-Name` header. It needs the edit token when one is set. New error code: `invalid_document` (422).
- The Import control in the bar takes a file from the browser's file dialog, or one dropped on the canvas, and imports it after a second press. A browser without the edit token is told that importing needs it.
- JSON export is the editor's own, in its menu under "Save to…". The file is named after the slot's title.
- Tests for it: `tests/test_import.py`, more of `tests/test_saver.py`, `tests/test_room.py`, and `tests/test_repository.py`, `web/src/importing.test.ts`, and `web/e2e/import.spec.ts` (T-009, and the import part of T-008).
- The edit link (S-008, D2-032). A link to a slot, or to segl's root, that ends in `#e=<token>` makes a browser an editor. The page takes the fragment out of the address at once, says `hello` with the token, and stores it under `segl:{basePath}:editToken` once the server has taken it. A wrong token is not stored and does not take the place of a stored one. A link opened in a tab that is already on a slot, and a token another tab stored, take effect without a page load. `docs/DEPLOY.md` says how to write a link.
- The notice in the bar says where this browser stands with the edit gate (S-016): that it has the token and can edit, that editing is locked for want of the token, or that segl did not take the token it has.
- Tests for the edit gate in a browser: `web/e2e/token.spec.ts` (T-008), against a second test server that has a token, directly and through nginx at `/board/` and at a host root. `web/e2e/origin.spec.ts` shows a page of another site refused by the Origin check, for a request and for the collaboration socket (T-012).
- `tests/test_sweep.py` is T-012 as one walk over every route: no answer sets a cookie or carries a CORS header, a mutation or a WebSocket upgrade from another site is `bad_origin`, and a mutation without the token is `view_only`, in process and through nginx. A route that is added and is not in the walk fails a test.
- A task for access codes, T10b, is in the queue (D2-033). The site will list codes or phrases beside a server secret, a browser will enter one on an access page and be issued a signed pass with its time of issue, which the site can limit in hours or end, and `internal_networks` will close segl to every other address. Not built yet.

### Changed

- The packaged nginx site examples are hardened: TLS 1.2 and 1.3 only, forward-secret AEAD ciphers under 1.2, no session tickets, no nginx version, and `X-Content-Type-Options`, `Referrer-Policy`, and `X-Frame-Options` beside HSTS, on nginx's own answers too. `docs/SECURITY.md` has a section on hardening nginx, which says that ports, TLS, and headers are the site's, and that the MVP is for an internal network. `tests/test_mount.py` holds the examples to it, each in an nginx of its own for the TLS settings.
- `edit_token` is 1 to 256 printable ASCII characters with no space at either end, or empty for none. segl stops with exit status 2 for any other value. A browser sends the token in a request header, which carries nothing else whole, so such a token never worked from a page: drawing went through, and every title, restore, import, and upload failed.
- The Python pin is exactly 3.15.2 and follows the newest stable CPython uv offers. GitHub Releases are the publish destination. PyPI stays off until there is a demoable build.
- The contributor manual lives in `docs/`. `draft1/` and `draft2/` stay in the repository: frozen history, and the agent workbook.
- segl no longer has a `base_path` setting. It serves at its own root and works under any path nginx strips, such as `/board/` (D2-007).
- The web package uses npm, the newest Node LTS release, Vitest, Playwright Test, and Prettier (D2-023).
- Releases follow vakr's and Sunstone's policy. Every component moves to its newest release, a release that fails the tests is held with the reason, and currency is checked again at publish (D2-020). The release command is now task T01b.
- Development containers may run under rootful Docker (D2-015, S-017).
- The WebSocket carries title changes and newly placed images. Uploaded files are served at `/api/v1/assets/{hash}`. `trusted_proxies` decides whose `X-Forwarded-For` segl believes.
- segl's default address is `127.0.0.1:8888`, not port 8000, which other development servers commonly use. The upstream in `deploy/nginx/segl-http.conf`, `deploy/segl.toml.example`, and the Vite dev server's proxy follow. The mount tests take the upstream to replace from the default, so the nginx file cannot fall out of step with it.
- The default display names no longer include Bush, Clinton, Obama, Trump, or Biden.
- The test client's transport is httpx2, not httpx, which Starlette deprecates there. `versions.toml` gains `[python.build]` for the build backend.
- The browser tests run one at a time, and no longer expect an empty slot: the slots are shared, and a room keeps what a test drew. `web/e2e/pages.ts` says which slot each kind of test may change.
- A participant has no `color` in the WebSocket messages. The pinned editor colors a cursor from the connection id and takes no other. `welcome` gained `connectionId`, and the client's `presence` is a cursor alone.
- `GET` and `PATCH` of `/api/v1/slots/{n}` are one route, so a `405` there names both in `Allow`.
- `GET /api/v1/slots/{n}/scene` returns the head as of the last flush, with the deleted elements and the files its images name. Before, the head never changed after startup.
- The `elements` message takes an optional `seq`, and may be an empty list. `scene` carries the slot's files.
- A history row for a head that an earlier flush wrote, as after a restart, carries that head's label and not `System`.
- The test harness (`tests/harness.py`) quotes the servers' logs when it gives up on one. A WebSocket handshake that is not answered fails with the end of segl's log, and through nginx of nginx's two logs as well. A server that had to be killed after SIGTERM is named in a warning with its log. `tests/test_harness.py` covers both.
- `Room.restore`, which took back a snapshot that was not written, is `Room.take_back`. A restore is now something else.
- The bar's connection state has five values: connecting, live, saving, saved, and disconnected. The browser tests wait for "in the room", which is any of the middle three, where they used to wait for `Live`.
- The editor's own way to open a scene file is off: its menu's Open, Ctrl+O, and a scene file dropped on the canvas. Each put the file in one browser's canvas and not in the slot. A dropped scene file is now offered for import.
- The History control marks the first row of an epoch `replacement`, where it said `restore`: a restore or an import wrote it, and nothing stored says which.
- `Repository.replace_head` takes `files=`, for the files an import brings. `Room.put` puts elements and files in place of a room's scene, and `Room.replace` reads a stored scene and calls it. `Saver.put` is the import beside `Saver.replace`.
- The test harness's client speaks TLS 1.2 to the test nginx. Under TLS 1.3 its WebSocket client sometimes lost its request on a busy machine, which failed a test through nginx about once in a thousand handshakes, and twice in CI.
- The license header moved from the agent rules to `CONTRIBUTING.md`. The rule to comment out superseded code was removed.

### Fixed

- A viewer's canvas takes nothing that is dropped on it. The editor's view mode does not cover a drop, so an image dragged onto the canvas of a browser without the edit token was placed there, for that browser alone. The server had refused it all along.
- A hand-made `elements` message with a number too large to hold, such as `1e999`, is `bad_message`. It used to be taken: Python read it as infinity, the other browsers were sent `Infinity`, which is not JSON, and the slot's stored scene could then not be loaded by any browser. No browser sends such a number.
